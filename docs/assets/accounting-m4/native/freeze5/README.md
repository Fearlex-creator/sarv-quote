## Reproduction and manual demonstration

```sh
source /workspace/sarv-environment/activate.sh
G_DEBUG=fatal-criticals SARV_QA_BINARY=/workspace/sarv-evidence/bin/sarv-M4-freeze5 dbus-run-session -- /usr/bin/python3 scripts/procurement-qa.py
```

Both included short/guard observers require the same binary and `SARV_M4_NATIVE_FIXTURE` pointing at a completed synthetic `full` profile. Controlled completion reproduction additionally needs the documented M3-before fixture and locally compiled private delay shim; see its separate README. No SQLite database, executable, runtime directory or customer data is included.

For a manual synthetic walkthrough: Alt+8 purchases, Ctrl+F REC-A, one Tab, Enter to read its source. Tab to the disclosure, Space expands exact IDs, Escape closes. ShiftTab accesses the toolbar. Alt+9 inventory; inspect paired transfer and end-of-day controls. Refresh shows both ready labels. Open a purchase order, add/edit/remove staged lines, use catalog price provenance, review exact amount, and cancel. A rejected preview shows a global error; a successful one explicitly says reviewed and not yet posted. Unposted staged inputs are not durable drafts. Posted history remains immutable.

Direct synthetic injection of dead-page/stale catalog-key and stale review-revision completion branches was not part of these GUI cases; their status-only source changes are independently reviewed, and existing native catalog and review paths execute in full30. This evidence does not establish production readiness, Iranian tax compliance, Wayland/Windows behavior, screen-reader speech or universal workflow parity. Later sales/COGS/returns, cash/cheques, closing and statutory modules remain gated; financial migration/recovery, independent review and performance have separate evidence.
