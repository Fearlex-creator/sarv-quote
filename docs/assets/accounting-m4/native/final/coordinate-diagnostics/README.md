# Rejected coordinate assertion

The first final short run correctly recorded real Tab focus and produced visually readable screenshots. Its added containment assertion used AT-SPI SCREEN extents, which report x=0,y=0 for every widget in this runtime. Those values do not establish widget position. The original report/observer/log/provenance are retained here, and their numerical containment claim is rejected. No wrong-page product defect was found: the disputed inventory image header reads «موجودی و انتقال», and the two pages intentionally share their documents tab. The revised observer uses settled GTK-native keyboard events, compute_bounds against the actual root window and nearest scroll viewport, and explicitly checks active-page identity. Production source is unchanged.

The first revised GTK-coordinate probe recorded real focus bounds but the observer wrongly required the GTK client/root size to equal the requested X window/screenshot size. For a 900×560 capture, GTK reports 890×550; the recorded button [611,489,258,34] is within both GTK root and scroll clip [0,46,890,477]. This observer-only failure is retained as outer-client-mismatch files. The final observer checks the actual GTK root and clip, records both coordinate systems, and waits 250 ms after focus before the harmless modifier-key snapshot.
