## Additive production-action protocol

Production hooks belong to root/native ownership. Do not alter `scripts/native-performance-M2.py` or remove its original global, page, PDF or broad-save report fields. Run that unchanged external observer once on a new freeze. If internal probe phase preparation, capture scheduling or endpoint checks change, record the source diff and `observer_protocol_version`; the resulting broad C3 workflow has changed observer work and is not a controlled same-protocol causal comparison with C2. Preserve the original broad algorithm and disclose those changes alongside its result.

Add independently named action records rather than deriving action timings from numeric probe stages. Each record has a stable action ID, command name, origin (`native_signal` or `real_XTest_key`), monotonic start/dispatch/receipt/render/focus/end timestamps, current page/source IDs, generation and edit revision before/after, exact result, interval, full timer-gap array, terminal gap, tick count, max gap, and timeout/cancel/supersession reason. Record requested, installed and focused identities where they differ. Source traces carry the action ID and parent action ID so a save nested in navigation remains part of that navigation, and a PDF concurrent with Settings navigation is explicitly attributed. Existing source trace names remain available.

Start the independent20ms action clock immediately before dispatch of a real production command, before its snapshot clone, parsing, validation or worker preparation. End only after the entire acceptance endpoint below is observed. Include the final `end-last_tick` segment in its max and retain it separately; busy=false or a worker receipt alone cannot finish a render/focus action. No polling delay is added merely to manufacture ticks. A phase with zero ticks is unmeasured as a heartbeat acceptance check; if its observed terminal segment exceeds50ms, retain that observed miss. Record every cancelled, superseded, rejected, timed-out or partially complete phase, separately from successful phases. Missing records cannot pass.

Fixture injection, profile backup/hashing, synchronous screenshots and synchronous read-only DB verification occur before a scoped action begins or after it closes. No such work runs inside a scoped action. A screenshot is allowed after exact readiness/phase closure and after the previous capture completes, before starting a fresh independent action clock. The broad sampler continues to observe all those operations using its original algorithm. Never subtract their durations, discard their broad gaps or reset the global clock for the additive action protocol. Read-only DB equality can be verified outside the action; durable generation and worker receipt identity come from production state/receipt metadata. Exact native readiness must use the rendered current identity and visible, sensitive allocated control, plus actual required focus. Source phase completion alone is corroborated by external native observation, not assumed to prove all pixels.

Production action hooks should observe work rather than change validation, revisions, persistence, focus or user behavior. Where an async command is superseded, record its cancellation and require the succeeding current command to finish against its own exact identity; never count a stale row/receipt as readiness. Document the C3 request-time invalidation and unchanged setter behavior with source traces and functional evidence. A shorter source-named setter span does not prove overall usability or superior speed.
