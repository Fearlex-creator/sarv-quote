# Bounded external cached-node observer proposal

Proposal only; not implemented or measured. Root requested this after candidate6 qualification exited. The original M5 observer and all C2/C5 samples remain unchanged. This is a new explicitly declared observation method, not a causal product-speed comparison or revised budget.

Static source supports caching Sales nodes for the lifetime of one owned workspace/dialog. `src/ui/sales.rs:1125` constructs25 persistent main-list card/title/summary/action objects; render at1505 updates their current identities/text/sensitivity/visibility without replacing them. Search/status and list pagers are persistent. Editor `initialize_lines` at2203 creates25 persistent line summaries/actions plus pager/marker; `render_lines` at2280 updates the current line mapping, text and sensitivity. Exact persistent mapping is independently qualified by root's native34-distinct-ID evidence. Persistent GTK objects alone do not prove persistent AT-SPI object identity across hide/reveal or root retirement; runtime qualification must establish that too.

Limit an explicitly versioned M5 external-observer delta to120-draft/posted Sales queries and1,000-line Sales pages. Cache the current search/status, slot0 title/summary/action and pager nodes under the current workspace/dialog **before** timed dispatch. Core/procurement/startup and all production/compiled M2 observers stay unchanged. The historical timed endpoints stay exact current query/count/draft reference plus visible sensitive Continue/Detail, and exact current long-page marker plus visible sensitive Edit, then actual focused usable action. Preserve the original component-first focus/Tab fallback and visible-phase focus assistance; do not introduce a dispatch-only or new all-Tab endpoint.

Inside timed readiness, clear each cached node's AT-SPI cache and reread current name/text/role, states and rectangle. Require exact current draft reference/count/search value or exact long-page marker, retained current root/process and parent relationships, the correct action caption, visible/showing/sensitive positive allocated geometry, then exact actual focus for the focused endpoint. A matching page marker with an old retired-root button cannot pass. Do not infer a visible line UUID: the old endpoint has no such field. `libatspi.so.0` exposes `atspi_accessible_get_accessible_id`/attributes, but whether GTK exposes the changing `sales-line-0-index`/`sales-open-id` widget name is not yet observed. Optional actual API ID receipts can corroborate identity if available; absent IDs must not be invented or weaken existing predicates.

Cache lifetime ends when its owned process/root/dialog ends. Runtime qualification records node/root/process identity before/after zero-result hide/reveal, alternating queries, all3 filtered pages, all40 line pages and dialog reopen. Reject defunct, wrong-parent, wrong-role or retired-root nodes. If a cached node becomes invalid during a timed action, preserve the failed scope/sample and stop; do not silently fall back to traversal or accept a stale control. Any bounded rediscovery must occur before a separately declared subsequent dispatch and be recorded. Discovery from an initial populated page may use the original untimed initial state; if an extra calibration query is necessary, declare its warm-up/cache effect explicitly.

Record observer protocol/hash, discovered node identity/parent, cache validity and exact readiness receipts, plus counts/durations of discovery and timed predicate calls where practical. Native callbacks and every read-only generation/payload check remain verified. Functional qualification uses fresh outputs and n1/n2 diagnostics only, with all failed older versions preserved. Only after qualification and root quiet GO may a new immutable final observer epoch run. The reduced discovery work changes observer overhead even when the semantic endpoint stays the same; report C2/C5 original and cached-method results separately, retain all50/150/200ms misses, and make no product-only latency improvement claim.
