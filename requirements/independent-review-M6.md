Scope is an operational receipt's unbilled original-cost stock return (Dr GRNI / Cr Inventory) and a specific matched bill line's billed original-cost return paired atomically with a linked supplier credit (Dr AP / Cr Inventory). Frozen original item, supplier, warehouse, quantity and value are authoritative. Return and supplier credit have distinct stable IDs/references/states with reciprocal lineage. Return does not replenish purchase-order receiving quantity. Settlement/refund, standalone credit, current-cost variance, damaged stock, opening-AP credits, invented receipt provenance and statutory tax remain deferred. No production, full PUR/INV/G3/G4, professional accountant or legal acceptance is implied.

## Source and allocation rules to seal

1. A billed return names the actual operational receipt and exact bill line; supplier and all frozen source identities must match. Return quantity/value allocation is cumulative from that bill line's original quantity/value; the final return consumes its exact residual. It cannot consume another bill line's residual or infer provenance from an aggregate AP balance.
2. Bills and unbilled returns consume ONE receipt allocation stream. For original receipt Q,V, each incremental consumption is `half_up(V × cumulative_consumed_Q / Q) − already_consumed_V`, with the final residual exact. Consumed quantity includes billed quantity and unbilled-returned quantity. Billed returns reverse AP and stock, but do not reopen the receipt's consumed/unbilled quantity or its original PO remaining quantity. No rebill after return.
3. Mixed receipt billing/return histories retain both original and remaining quantities/values. Separate cumulative counters for bills and unbilled returns would double spend rounded rials and are unacceptable. A receipt3 pieces/value1: bill1 allocates0; unbilled return1 allocates1; final bill1 allocates0. Later bill-line returns reverse0 and0 respectively, not a second1.
4. Return is a stock OUT from the frozen original warehouse at original attributable value, never current moving average. Current pool must have both quantity and value sufficient. If taking all pool quantity would leave any pool value, reject atomically. Never remove a different value, create a variance account, strand value at zero quantity or borrow quantity/value from another warehouse. An actual zero-value original return is supported with stock provenance and audit and no empty journal.
5. Financial/source state, paired IDs, stock movement, original allocations, AP/GRNI detail, numbering, request aliases and audit commit together. Exact retries preserve the one existing effect even after a lock; changed full content/revision/provenance with same or fresh key fails. All-revision natural source/event uniqueness and global document/request namespaces apply across all modules.
6. New stock return date is at least the global company stock date and actual source availability date; a bill-line return also respects matching/allocation chronology. The company/period/setup and financial/source dates are validated independently. Same-date interleaving uses persisted sequence, not module concatenation or UUID. Locks reject new effects everywhere; no generic reversal of typed return/credit effects.

## Adversarial acceptance matrix

- **Tiny residual:** independent new receipt Q3000,V1; bill1000=0; unbilled return1000=1; final bill1000=0. Original receipt allocation consumes totalQ3000/V1 exactly. Both bill returns1000=0. Probe one return command with multiple lines so offsetting wrong per-line supplied values cannot pass a correct document total. Partial billed line Q3000,V1 return costs0,1,0; final exact conservation. Reject fractional/negative/zero quantity, overflow and supplied-cost mismatch.
- **Free stock:** explicit zero-price PO/receipt/bill/return keeps real positive quantities, IDs, source lineage and nonfinancial audit; no empty journal, invented1IRR or discarded movement. A free-cost return that exhausts a mixed pool with positive residual value must reject.
- **Current-pool safety:** sufficient quantity but insufficient original value rejects; sufficient value but insufficient quantity rejects; exact full-pool depletion succeeds only when its value equals original return value; full quantity with excess pool value rejects. Verify stock/GRNI/AP/journals/requests/generation byte-for-byte unchanged on rejected preview/post. Different warehouse/item/company funds cannot rescue an invalid original pool.
- **Source eligibility:** unknown source, opening AP/GRNI without operational source, receipt line from other receipt, bill line from different supplier, same ID reused across return/credit/receipt/delivery/journal, duplicate return references, changed frozen units/warehouse/item, return above remaining billed/unbilled quantity, and unbilled return of fully billed receipt reject. Each source's chronology and original Q/V remain visible.
- **Interleaving:** purchase receipt→sale→transfer→purchase return→sales return on the same date must replay identical pools and sequence across restart/restore. Source receipt consumption is shared across partial bills/returns; returned quantities cannot be billed/received again. Tampered sequence/before-after pools/source allocated values/credit links and shuffled histories must reject or replay in the explicitly supported canonical order without changing effects.
- **Identity/retry:** same key/content and fresh key/exact content return one result; same key changed quantity/value/date/reason/reference/revision rejects; fresh key changed content for already posted source/event rejects; source_revision does not permit a second economic event. Distinct sources colliding in request or document namespace reject. Same-key and fresh-key concurrent processes produce one effect or a documented conflict followed by exact replay, never two effects.
- **Dates/locks:** before receipt, before matching bill, before source's latest allocation date, before company latest stock date, outside period, wrong company/setup and locked new post all reject atomically; successful existing retry after lock returns original. Old report cutoffs remain unchanged. Gregorian/Jalali and rial/toman display changes leave economic dates/values invariant.
- **Durability:** actual Store CAS stale generation rejection; SIGKILL around staged/transaction/commit boundaries followed by fresh process/retry and integrity checks yields either complete old or complete new financial/operational pair. No lone credit, movement, request or audit. Capture raw full State, SQLite integrity, balances, aliases and all source quantities, not totals alone. Hardware power loss/disk full remain untested unless separately executed.
- **Migration/restore:** genuine schema6 M5 fixture upgraded6→7 only after verified original recovery. Preserve immutable procurement/sales/opening/manual/quotation/policy prefixes and original hashes/totals/IDs. Fresh profile restores the complete schema7 state and report cutoffs with returns/credits/aliases intact. Actual archived M5 executable refuses schema7 without altering its bytes/generation/schema. Corrupt/tampered checksum/links/allocations fail before replacement. No normalized rebuild masquerading as original recovery.
- **Native/export:** compiled GTK4/libadwaita; actual source selection, quantity input, accounting preview, paired distinct documents, retained bad input, double-click/retry, focus, keyboard-only completion, search/source drilldown, status, restart, light/dark standard+narrow and loading/error completion. Actual PDF/CSV amounts, original cost/source links, currency/unit, dates and all pages visually inspected. Reports include updated AP/GRNI detail plus unchanged sales controls at each cutoff. Preserve quotation, settings, Jalali/manual books, M4 purchases/transfers and M5 sales/drafts/conversion workflows.
