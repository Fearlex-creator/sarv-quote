## Scope and authority

The next bounded slice completes a usable **original-receipt-linked operational purchase return paired with a supplier credit**, after M5 and before operational treasury. It preserves `core-policy-v1`: accrual/perpetual stock, integer IRR, base-unit thousandths, exact frozen unit conversion, positive half-up cumulative original allocations/final residual, moving weighted-average company/item/warehouse pools, no negative stock, company stock sequence and nondecreasing stock financial dates. User-delegated guide defaults authorize synthetic implementation; professional production review remains pending.

A billed return and its financial credit retain **distinct stable IDs, references, states and source-line links**, but commit as **one event on one permitted financial date**. An unbilled return carries no supplier-credit metadata; it clears original operational-receipt GRNI within that same atomic event. Original receipt/bill and policy/party/item/warehouse provenance survive later master-data edits, restart, export and restore. Preview shows physical quantity, original attributable value, remaining eligibility, AP/GRNI and stock consequences. A cancelled/invalid preview has no effects. Returns do **not** reopen PO received quantity or permit re-receiving the returned quantity.

In scope: eligible unbilled operational receipt and eligible billed operational receipt/bill portions, partial then residual returns, same/fresh-key retry, current and historical AP/GRNI/inventory reconciliation, native entry/review/source trace and labeled CSV/PDF/export/backup/restore evidence. Bill matching after an unbilled return must exclude returned original quantity/value. Supplier credits reduce only a proven eligible original liability; AR and any dual-role customer's balance remain separate.

Excluded: refund, payment, bank/cash/cheque movement, settlement or independent credit application, excess/unapplied supplier credit, advances, price/landed-cost variance, damage/scrap/disposition, arbitrary unlinked return, opening-only GRNI/AP physical return, mixed receipt/bill modes or inferred source mappings, manual return price override, posted edit/reversal/cancellation, negative/backdated stock recosting, reopened PO, counts, complete reports/closing/permissions, tax/statutory and advanced modules. | Event | Required financial and operational effect | Validation / exact conservation |
| --- | --- | --- |
| Unbilled return | Dr GRNI / Cr Inventory at original attributable receipt value; source-warehouse stock out; return state `Returned`, no credit ID/reference/state. | One operational receipt per command. Reduce its shared bill/return cursor once. No AP, cash/bank, COGS, revenue or invented adjustment. Opening-only GRNI returns reject. |
| Billed return | Dr AP / Cr Inventory at original attributable receipt/bill value; reduce that original supplier payable remainder; source-warehouse stock out; distinct linked return `Returned` / credit `Posted` identities. | Original bill line and receipt line must agree; amount cannot exceed eligible original AP/quantity/value. | Partial/final return | Unbilled: `half_up(receipt value × cumulative consumed quantity / receipt quantity) − prior consumed value`, where consumed includes bills and unbilled returns. | Zero-value eligible return | Provenance, quantity, source and audit remain; no empty/all-zero journal and no invented money. | Billed zero-value returns still retain credit identity/state; unbilled mode has no credit metadata. | Reconciliation | Inventory movement value = GL inventory; AP detail = AP; unbilled quantity/value = GRNI; COGS/AR and every other opening control remain consistent at identical cutoffs. | Missing/unsupported control is unavailable/error, not verified zero. The original warehouse's **current** pooled quantity must cover the return quantity and pooled value must cover the **original** attributable value. If the withdrawal leaves quantity zero, its remaining value must also be zero. Block insufficient quantity, insufficient value, or orphan value at zero quantity **without mutation**. The current MWA value is not authority to change a return's original value. No variance/suspense/loss adjustment account is introduced to force success. A future adjustment/disposition design would need separate policy and proof.

Enforce company/source/line/supplier/warehouse/unit/reference integrity, positive checked quantities, exact source totals, original source availability, latest allocation date, latest company stock date and period locks at the command boundary. One command uses one mode: all unbilled lines belong to one receipt, all billed lines to one bill with exact receipt correspondence and required credit ID/reference. A bill may contain multiple operational receipts; each line preserves its original warehouse. A source portion cannot be both billed and unbilled or returned twice. Normalized supplier return-reference/date and credit-reference/date reject duplicate paper documents from a fresh source ID. Attempted independent credit or multi-date stock/financial posting rejects. Historical already-committed identical retry after a later lock returns the existing effect; a new return must satisfy locks and dates.

Natural identity `(company, source, event)` permits one economic effect across all revisions. Identical same/fresh-key commands alias that effect once; changed quantity, value, source link, date, reason or revision conflicts. Request/document/line/movement identities cannot collide across manual/core-zero/procurement/sales namespaces. Source state, remaining allocations, paired IDs, journal or nonfinancial marker, stock out, AP/GRNI, sequence/number/audit and request aliases commit atomically; detached writers use durable Store CAS. Restore/replay merges all trade history by company sequence and rejects forged original/before/after pools or duplicate sequences.

## Sealed command and eligibility contract

`ProcurementCommand::Return(ReturnPurchase)` posts `procurement.return.v1`. `ReturnPurchase` uses existing `ProcurementContext`, supplier, return ID/reference, optional credit ID/reference, paper `document_date`, return lines and exact supplied total. Each `PurchaseReturnLine` has ID, operational `receipt_line_id`, optional exact `bill_line_id`, positive **BASE-unit thousandths** and exact supplied value. Existing preview/post/document/reconcile APIs handle this event.

`procurement_receipt_returnable(company, receipt_line)` and `procurement_bill_returnable(company, bill_line)` expose frozen original and remaining quantity/value, supplier/item/warehouse, date/reference and bill links. UI previews use those cursor parameters with checked integer arithmetic. Frozen `PostedPurchaseReturn` retains state `Returned`, optional credit state `Posted`, exact original receipt/bill record identity exclusively for its mode, source-linked lines and total; replay validates those states/links.

Unbilled bills/returns consume one cumulative original receipt Q,V stream. Example **receipt3/value1 → bill1/value0 → unbilled return1/value1 → final bill1/value0**. Later first/last bill returns reverse0/0, never another share of receipt1. Billed returns consume their own original bill-line Q,V; they do not reopen GRNI or PO eligibility. Mixed-mode/mixed-source commands and opening-only physical returns reject. Paper document date is distinct from financial date and no later; source/allocation/latest-stock/period checks apply at commit.
